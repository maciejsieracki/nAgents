# MVP2 — Zarządzalność

**Cel: administrator przestaje dotykać plików. Uprawnienia płyną z katalogu firmowego,
budżety blokują, operacje nieodwracalne wymagają kliknięcia człowieka.**

Wycena: **12–15 dni roboczych.** Zakres rośnie do sześciu agentów projektowych
i pierwszych agentów stanowiskowych.

---

## 1. Zakres

| # | Element | Opis |
|---|---|---|
| 1 | Panel administracyjny | agenci, nadania, budżety, użytkownicy — przez interfejs, nie przez plik |
| 2 | Synchronizacja z katalogiem | Microsoft Graph: grupy, członkostwa, wyłączone konta |
| 3 | Obsługa odejść | wykrycie zniknięcia z katalogu, odebranie dostępu, zgłoszenie następcy |
| 4 | Budżety z twardą blokadą | limit na agenta, zespół i najemcę; przekroczenie zatrzymuje |
| 5 | Podgląd kosztów | zużycie per agent, per człowiek, per model, dzień i miesiąc |
| 6 | Zatwierdzenia operacji | operacje nieodwracalne wstrzymane do decyzji człowieka |
| 7 | Audyt z odrzuceniami | filtrowanie, eksport, widok prób nieudanych |
| 8 | Agenci stanowiskowi | rodzaj `stanowiskowy`, powiązanie z projektowym, bez własnych kluczy |
| 9 | Kopie zapasowe | harmonogram + **przećwiczone odtworzenie** jako element odbioru |
| 10 | Agent zarządzający | opcjonalnie: te same operacje wydawane w rozmowie |

## 2. Poza zakresem

- Wspólna pamięć i poziomy kontekstu (MVP3)
- Rutyny i wyzwalacze (MVP3)
- Kanał Teams (MVP3)
- Tokenizacja (MVP4)

## 3. Synchronizacja z katalogiem

Zadanie cykliczne co 15 minut plus wywołanie ręczne z panelu.

```
1. Pobranie grup wskazanych w rejestrze (Microsoft Graph)
2. Pobranie członkostw każdej z nich
3. Różnica względem stanu w bazie
4. Zastosowanie:
   ├─ nowy członek grupy      → dostęp do agentów tej grupy
   ├─ usunięty z grupy        → dostęp odebrany, wpis w audycie
   ├─ konto wyłączone         → wszystkie dostępy odebrane, sesje unieważnione
   └─ konto zniknęło z katalogu → jak wyżej + zgłoszenie „stanowisko bez obsady"
5. Wpis w audycie dla każdej zmiany, z powodem „synchronizacja katalogu"
```

**Zasada:** synchronizacja **nigdy nie nadaje uprawnień, których nie ma w rejestrze**.
Rejestr mówi „grupa Księgowość ma dostęp do agenta księgowości"; katalog mówi tylko,
kto jest w tej grupie. Odwrócenie tej zależności oznaczałoby, że administrator katalogu
może nadać dostęp do dowolnego agenta.

## 4. Budżety

Trzy poziomy, wszystkie egzekwowane w bramie modeli:

| Poziom | Przykład | Po przekroczeniu |
|---|---|---|
| Agent | księgowość — 200 USD/mies. | agent przestaje odpowiadać, komunikat dla użytkownika |
| Zespół | sprzedaż łącznie — 600 USD/mies. | wszyscy agenci zespołu wstrzymani |
| Najemca | cała firma — 2000 USD/mies. | wstrzymanie z natychmiastowym powiadomieniem właściciela |

**Blokada, nie powiadomienie.** Limit, który tylko ostrzega, nie chroni przed rachunkiem.

Ostrzeżenia przy 70% i 90% wykorzystania. Podniesienie limitu to operacja z zatwierdzeniem,
zapisywana w audycie — bo inaczej limit jest fikcją.

## 5. Zatwierdzenia

Operacje wymagające decyzji człowieka, definiowane per agent:

```yaml
approvals:
  - wzorzec: "wyslij_email"        wymaga: owner
  - wzorzec: "zapisz_rozliczenie"  wymaga: owner
  - wzorzec: "usun_*"              wymaga: owner
```

Hermes ma mechanizm zatwierdzeń wbudowany; nAgents dokłada dwie rzeczy:
**kto może zatwierdzić** (rola z rejestru, nie ktokolwiek w rozmowie) oraz
**zapis w audycie** — kto zatwierdził, kiedy i co dokładnie.

## 6. Agenci stanowiskowi

Wchodzą w MVP2, z twardym ograniczeniem z reguły 6.3:

```yaml
  - slug: handlowiec-polnoc
    nazwa: "Handlowiec — region północ"
    rodzaj: stanowiskowy
    parent: sprzedaz          # domena, przez którą sięga po dane
    hermes_profile: handlowiec-polnoc
    model_default: <model tani>
    budget_monthly_usd: 40
    grants:
      - typ: user
        upn: "a.kowalska@naster.pl"
        rola: user
    secrets: []               # WYMÓG: pusta. Walidator odrzuca inaczej.
```

**Walidator rejestru odrzuca agenta stanowiskowego z niepustą listą sekretów.**
To nie jest konwencja, tylko reguła egzekwowana przez narzędzie.

### Przejęcie stanowiska

Profil jest stanowiskiem, nie osobą. Przejęcie to zmiana jednego pola:

```
nagents agent reassign handlowiec-polnoc --z a.kowalska@naster.pl --na m.wisniewski@naster.pl
```

Skutek: dostęp odebrany poprzedniej osobie, nadany następnej, dorobek stanowiska
nietknięty, wpis w audycie. Pamięć prywatna — patrz MVP3, punkt o rozdzieleniu warstw.

## 7. Panel administracyjny

| Ekran | Zawartość |
|---|---|
| `/admin/agents` | lista, stan, budżet, wykorzystanie, ostatnie użycie |
| `/admin/agents/{slug}` | edycja: model, budżet, nadania, zatwierdzenia |
| `/admin/users` | lustro katalogu, do których agentów kto ma dostęp |
| `/admin/costs` | zużycie: agent, człowiek, model, dzień i miesiąc |
| `/admin/audit` | dziennik z filtrami, eksport CSV |
| `/admin/sync` | stan synchronizacji, uruchomienie ręczne, historia zmian |

Dostęp wyłącznie dla roli `owner`. **Każda zmiana w panelu zapisuje się w rejestrze
i trafia do gita** — panel jest wygodą, a nie obejściem wersjonowania.

## 8. Scenariusze odbioru

| # | Scenariusz | Oczekiwany wynik |
|---|---|---|
| 1 | Dodanie osoby do grupy w Entra ID | Dostęp w ciągu minuty, bez działań administratora |
| 2 | Wyłączenie konta w Entra ID | Dostęp odebrany, trwające sesje unieważnione |
| 3 | Usunięcie osoby z grupy | Dostęp do agentów tej grupy odebrany, inne bez zmian |
| 4 | Przekroczenie budżetu agenta | Agent wstrzymany, komunikat czytelny, właściciel powiadomiony |
| 5 | Próba podniesienia limitu przez osobę bez roli | Odrzucenie, wpis `deny` w audycie |
| 6 | Agent próbuje wysłać korespondencję | Wstrzymanie do zatwierdzenia; bez zatwierdzenia nic nie wychodzi |
| 7 | Rejestr z agentem stanowiskowym mającym sekret | `registry validate` odrzuca z komunikatem |
| 8 | Przejęcie stanowiska | Następca widzi dorobek, poprzednik traci dostęp natychmiast |
| 9 | Zmiana budżetu w panelu | Widoczna w gicie jako commit |
| 10 | **Odtworzenie z kopii zapasowej** | Przećwiczone, udokumentowane, poniżej godziny |

## 9. Ryzyka etapu

| Ryzyko | Reakcja |
|---|---|
| Uprawnienia do Microsoft Graph wymagają zgody administratora dzierżawy | Załatwić równolegle z MVP1, nie na starcie MVP2 |
| Synchronizacja co 15 minut to za rzadko przy zwolnieniu dyscyplinarnym | Ręczne „odetnij natychmiast" w panelu, dostępne bez czekania na cykl |
| Panel zaczyna rosnąć w stronę parytetu z gotowymi platformami | Zakres zamrożony listą z punktu 1; reszta do `decisions.md` |
| Budżety okażą się za niskie i będą blokować pracę | Pierwszy miesiąc z limitami ustawionymi wysoko i obserwacją, potem dokręcanie |
